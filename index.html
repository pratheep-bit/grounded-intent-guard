Core Principle

The Flaw in String-Based Shell Safety

Every other shell safety system looks at words. Grounded Intent Guard looks at physics on disk.

1. Grounded Git Loss Detection

git reset --hard takes no path arguments. A string matcher thinks it's a standard reset. Grounded Intent Guard queries git status --porcelain live, counting staged & unstaged dirty files that would be permanently destroyed.

2. Raw Block Device Awareness

stat() on /dev/sda reports ~0 bytes because it's a special device node. Grounded Intent Guard calls blockdev --getsize64 to recognize a multi-gigabyte raw disk overwrite and triggers an immediate BLOCK.

3. Rolling Trajectory Drift

A sudden destructive command after 20 harmless dev commands represents human distraction or script anomaly. Drift is computed as 1.0 − (matches / window_size) without any ML training or embedding overhead.

4. Multi-Factor Recoverability

Is the repo pushed to upstream remote? Is trash-put installed as an undo bin? Are filesystem snapshots active? Irreversibility directly scales the friction tier so harmless actions aren't needlessly blocked.
